# 0010 对手建模优先于对手补丁

- 日期：2026-11-17
- 状态：采纳（细化 ADR 0009；不取代）
- 关联决策：ADR 0009（尾部优先、规则先于模型）、ADR 0001（RL 主路线）、
  ADR 0004（信誉成本）
- 对应计划：[plan 0001](../plans/0001-tail-first.md)
- 证据：[实验 0011](../experiments/0011-dev-pool-guard-generalization.md)

## 背景

ADR 0009 的方向是"先修尾部、规则先于模型"。T1 的 `guard_open`
（对手首手 B → 我第 2 手 B）在 130 留出池上拿到 +1.30，看似验证了方向。
但 T3 建好独立 dev 池后，同一规则在 dev 池上是 **-0.62**（worst -2.61），
没有复现收益。

机制很清楚：

| 对手 | 首手 | 试探规则 | 对第 2 手合作 | 对第 2 手背叛 | 正确应对 |
|---|---|---|---|---|---|
| 130 `prober` | B | B-C-C | 永久背叛（惩罚合作） | 退回 TFT | 第 2 手背叛 |
| dev `opening_probe` | B | B-B | 转为合作（奖励忍让） | 永久背叛（惩罚报复） | 第 2 手合作 |

两者在 `length == 1` 的可观测信息完全一样（"首手 B"），正确动作却相反。
一条无条件的"首手 B → 我 B"规则必然在其中一边出错。这不是"规则不够多"，
而是**线索不够、且把单一线索硬编码成了动作**。

继续按测试集尾部逐个加 `if` 分支，会重演同一个问题：在 130 上修好一个
对手，在 dev / 真实考场触发另一个对手，且规则之间互相干扰、不可组合。

## 决策

1. **提交候选不允许针对具体对手/单一线索的硬补丁。** 规则不得以对手名、
   某个测试集对手的签名、或单个低信息量线索（如"首手 B"）直接决定动作。
2. **允许的规则必须是可观察行为特征上的通用机制**，例如"历史合作率高但
   本场背叛率高 → 提高惩罚概率"；阈值可以调，但输入必须是能跨对手
   泛化的特征。
3. **双边验证**：任何改动必须在 dev 池和 130 留出池上都**不降**，且效应
   超过同场克隆噪声；只在一边有效视为池特例，回退。
4. **主路线改为特征化对手模型 q + 原 DP**：DP 负责它已经解对的规划；
   q 由 `ipd/detectors/profile.py` 等行为特征估计（logistic / 浅 GBDT /
   类型后验）；DP 根据 q 选择动作，不做 `if 对手==prober` 的分支。
5. **尾部清单只作为"缺什么特征"的诊断**，不是补丁清单。实验 0009/0011
   的 worst-delta 列表用于设计特征与验证，不逐条硬修。
6. **`guard_open` 降级**：保留在 `ipd/agents/baseline_guard.py` 作为消融/
   机制证据，不进入提交路径；其洞察（首手模式、历史-本场不一致、
   prober vs probe）转入 T4 的特征集。

## 理由与权衡

- 真实考场对手未知；硬补丁的触发条件在分布外会误伤。guard 的
  130 +1.30 → dev -0.62 是直接证据。
- 硬补丁不可组合：每加一条，交互空间变大，回归测试只能覆盖已知池。
- 通用 q 模型的上限可能低于"针对已知池逐条修"，但它的收益更可能迁移到
  真实考场；这正是 ADR 0001 的泛化目标。
- 代价：通用模型需要训练数据与特征工程，短期可能不如硬补丁"好看"；
  用 dev 池 + 双边门槛控制风险。
- 保留规则作为"通用机制"是允许的：例如终局收益结构、immediate
  retaliation、history-current mismatch 都是可泛化的；被禁止的是
  **对手特定的例外**。

## 后果

- T4 从"尾部规则清单"改为"通用对手模型 v0（特征 q + DP）"；T5 为
  类型后验/决策聚焦 q 的进阶版。
- Plan 0001 增加"反模式"一节；T1 标注为"holdout 通过、dev 未通过、
  不作为提交候选"。
- 所有候选的验收改为：dev + 130 双边、效应 > 克隆噪声、0 故障、
  纯标准库/单文件。
- 基线仍是兜底；如果通用 q 模型在双边都拿不到正收益，提交基线。
