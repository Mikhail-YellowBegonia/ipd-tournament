# 0007 强化学习训练循环：REINFORCE + 价值基线 + 分阶段环境

- 日期：2026-11-17
- 状态：采纳（流水线与单测；阶段训练与 BC/DAgger 结果见 ADR 0008、实验 0008）
- 关联决策：ADR 0001（RL 主路线）、ADR 0003（训练/评测分离）、
  ADR 0004（信誉塑形为对冲）、ADR 0006（分阶段对手复杂度）
- 对应 issue：#6（路线图任务 8）

## 背景

`ipd/agents/encoder.py`（#5）已提供 1 ms 内的历史编码器与两项辅助损失；
`ipd/agents/baseline.py`（#3）提供了强参照尺；`ipd/pool/registry.py`（#4）按
ADR 0006 给出了四阶段对手池与历史隐藏配置；`ipd/eval/protocol.py`（#2）给出了
去重后的多配比评估。issue #6 需要把这几块接成训练闭环，并回答"每阶段是否超过
基线"。

issue 允许 REINFORCE 或 PPO，初版建议 REINFORCE。当前样本量下 PPO 的裁剪、
多 epoch 与 GAE 会引入更多超参数；先用更简单、可解释的 REINFORCE 把数据管线、
分阶段验收和检查点跑通，再根据阶段 3 的结果决定是否升级。

## 决策

### 算法

- **REINFORCE + 价值基线 + 熵正则**：回报为有限期（25 回合）折扣和，γ=1；
  价值头回归同一轨迹的归一化回报，advantage = 归一化回报 − 价值；
  策略损失 `-(logπ(a|s) · advantage) − β·H(π)`，价值损失 MSE，`β=0.01`。
- **辅助损失**：复用 issue #5 的 `NextMovePredictor` 与 InfoNCE 对比损失；
  下一手预测用真实对手下一步做标签，对比学习在同一场历史的两个随机掩码视图
  之间进行。权重默认 0.1 / 0.05，可关闭。
- **按回合长度分批**：编码器要求同一 batch 的本场长度一致；同一轮所有对局同步
  推进，天然按长度分组，不需要 padding。
- **回报/优势归一化**：回报按整批标准差缩放（价值损失与策略损失同量级），
  优势再做零均值/单位方差归一化，降低赛季之间的梯度尺度差异。

### 环境

- 一个"训练赛季"= 8 轮；每轮从阶段对手池无放回抽 `opponents_per_round` 个对手，
  同一轮的所有对局**并行**决策（对手函数是纯函数，对局互不影响）。
- 历史视图在每轮开始时生成、整轮不变，轮末统一追加，等价于模拟器的
  `history_update="round"`。课程规则中"本轮已完成对局是否进入历史"尚未确认
  （见 `docs/roadmap.md` 待确认问题 1）；选择轮末写入既符合"一轮内同时进行"的
  直觉，也让并行采集与模拟器语义一致。评测仍用模拟器的默认 `"match"`，
  训练/评测的这一差异由环境测试固定下来。
- 训练关闭 0.5 s 决策超时；对手异常/非法返回按合作处理。
- 奖励默认是单回合收益（一场 25 手之和即本场得分）；可选信誉塑形
  `−λ·无端背叛次数`（ADR 0004 的对冲项），默认 λ=0，先用纯得分训练。

### 分阶段与验收

- 阶段 1–4 的对手层、`hide_prob`、轮数来自 `registry.agents_for_stage()`/
  `config_for_stage()`；`schedule.py` 只负责阶段元数据与验收，不复制对手池。
- **regret 的操作化**：issue 要求"对 AllC/AllD/TFT/Gradual 的 regret 小于基线"，
  这里定义为相对基线的分差
  `regret(opponent) = baseline 对它的每场平均分 − 策略对它的每场平均分`；
  阶段 1 要求四个 canonical 对手的 regret ≤ 0，即逐对手不低于基线。
  这样"regret ≤ 0"与"不低于参照尺"是同一件事，且可直接从同一次评估中读出。
- 阶段 1：平均分 > 基线，且四个 canonical 对手 regret ≤ 0。
- 阶段 2：平均分 ≥ 基线 − 0.5，且 canonical regret 相对阶段 1 不回退超过 0.5。
- 阶段 3：平均分 > 基线；若测量了 `hide_drop_ratio`，要求隐藏历史导致的分数
  下降 ≤ 15%。"是否学到防范读历史对手"目前只记录笔记，尚未自动化。
- 阶段 4：种群自我对弈尚未实现（本次只保留 schedule 占位与 `self_play=True`），
  验收要求 `converged=True` 的指标，暂不满足。
- 训练中每 `eval_every` 个赛季用 1–2 个种子评估；最终验收用 5 个固定种子，
  并应接入 #10 留出池。评估把策略包装成确定性 `Agent`，与对手池 + 基线跑
  完整 8 轮锦标赛。

### 检查点与日志

- 检查点、JSONL 指标日志写到 `runs/rl/`（已 gitignore），不提交权重；
  `save_checkpoint()` 同时保存策略结构配置、优化器状态和训练超参数，
  `load_checkpoint()` 可恢复。
- 训练指标包含 loss 分量、熵、梯度范数、训练平均分与定期评估结果；
  每次评估附带 gate 结果，便于诊断。

## 理由与权衡

- **先简单后复杂**：REINFORCE 的方差比 PPO 大，但实现与调参面小；在 25 回合、
  收益三段的有限期问题上，价值基线 + 优势归一化已能显著降方差。
- **并行环境而非逐场模拟**：一个赛季 8 轮 × 20–30 个对手，逐场串行采集会让
  Python 循环成为瓶颈；按轮批量前向把编码器的 batch 用在刀刃上。
- **轮末写历史**：与并行采集一致；若调试包确认"同轮内立即写入"，需要把环境改成
  串行或按轮内顺序分块，届时只影响 `TrainingEnv`，训练循环不变。
- **regret 相对基线**：基线是 ADR 0001 指定的参照尺；用"分差"定义可避免为
  每个对手求最优应对（那需要额外的 oracle，且对手是参数随机的族）。
- **阶段 4 延后**：issue 标题限定阶段 1–3；自我对弈需要种群副本与不同的采样
  策略，放到下一轮实现，避免把未验证的种群逻辑混进首版训练闭环。

## 后果

- `ipd/training/` 新增 `policy.py`、`env.py`、`rl_train.py`、`schedule.py`；
  31 项单测（无 torch 时跳过），全量 163 项通过。
- 冒烟命令：

```bash
.venv/bin/python -m ipd.training.rl_train --stage 1 --iterations 2 --eval-every 0
.venv/bin/python -m ipd.training.rl_train --stage 1 --eval-seeds 0,1
```

- 一次 10 赛季的 sanity run（16 对手/轮，阶段 1）训练平均分从 −6 附近升到
  −2 附近，评估每场 2.50 → 3.82，基线 49.93；**尚未通过阶段 1 关口**。
  这说明流水线可跑通，但按现有超参数从零训练远未达到基线，需要后续做
  学习率/数据量/辅助损失/塑形项的扫描（issue 的"关键关口处理"）。
- 后续升级路径：PPO（若 REINFORCE 方差导致不收敛）、基线行为克隆热启动
  （ADR 0008 已采纳，与 #8 蒸馏共享代码）、阶段 4 种群自我对弈、#10 留出池
  接入最终验收。
- 训练端仍需与 #7 的纯 Python 推理对齐：`policy_agent()` 目前直接用 PyTorch，
  最终提交物要换成 `ipd/runtime/` 的实现，权重导出脚本应包含编码器常量。

## 替代方案

- **PPO/GAE**：更稳但超参数更多；等阶段 1/2 的 REINFORCE 结果出来再决定。
- **行为克隆热启动**：用基线当教师，先模仿再 RL；会削弱"端到端 RL"的纯度，
  但 issue 的关键关口处理允许回到阶段 2 增加数据量，热启动可作为诊断对照。
- **纯进化策略**（ADR 0005）：不依赖策略梯度，但样本效率低、与 #9 评测端绑定；
  作为 RL 失败时的备选，而不是首选。
