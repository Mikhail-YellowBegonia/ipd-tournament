# 系统架构

## 总览

```
训练端（不受限：numpy/torch）              评测端（纯标准库，对齐考试）
┌──────────────────────────┐   蒸馏(DAgger)   ┌──────────────────────────┐
│ 教师：大模型，读完整历史   │ ───────────────▶ │ 学生：n-gram 编码 + 小 GRU │
└──────────────────────────┘                  └──────────────────────────┘
        ▲  强化学习 + 辅助损失                         │ 导出权重为只读常量
        │                                             ▼
┌──────────────────────────┐                  ┌──────────────────────────┐
│ 模拟器 + 对手池 L0–L4     │ ◀──── 联盟快照 ── │ submission/gXX_*.py       │
└──────────────────────────┘                  └──────────────────────────┘
```

## 学生模型（部署形态）

1. **场内编码**：每场历史按（我方, 对手, 阶段）n-gram 计数，再乘可学习嵌入表求和。
   线性层可先计数后相乘，耗时只与词表大小有关，与历史长度无关。
2. **场间池化**：20 个场向量做带时间衰减的注意力池化；跳过隐藏场，输入有效场数。
3. **本场分析**：小 GRU 读本场动作对与位置，以历史嵌入为条件。
4. **输出**：合作概率；可用 `random` 采样，不改全局种子。

维度初定 16–32。所有推理包在 `try/except` 内，异常时有确定性兜底。

## 训练

- 主信号：强化学习，奖励 = 单场得分（可加信誉塑形项，见下）。
- 辅助损失（客观标签，来自模拟器，不构成"人类先验污染"）：
  - 预测对手下一手（用 19 场预测第 20 场）
  - 对比学习：同一策略的两场嵌入相近
- 蒸馏：学生自己下棋，教师在学生访问到的状态上给动作分布（DAgger），之后强化学习微调。

## 对手池

| 层 | 内容 |
|---|---|
| L0 | AllC、AllD、Random(p)、交替、周期模式 |
| L1 | TFT、TF2T、STFT、GTFT、Grim、WSLS、Gradual、Prober、Joss、ZD 系 |
| L2 | 感知回合：最后 k 手背叛、阶段切换、倒推背叛 |
| L3 | 读历史：基于检测器库（见下）决定防范、报复或剥削 |
| L4 | 联盟：我方各代快照 + 专门针对我方的克星 |

- 每个家族的参数随机采样，而非只放标准版本。
- 加噪声版本（1–15% 失误）和"出错退化为 AllC"版本。
- 用探针对手做行为指纹去重；按多种配比评估，报告平均与最差。
- 留出测试池：队友独立编写，只用于最终验收。

## 检测器库与信誉塑形

检测器是对一份 20×25 历史打分的函数，例如：终局背叛、最后 N 手背叛、起手背叛、
复读（TFT 式跟随）、剥削合作者、无端背叛率。同一套检测器有两个用途：

1. **构造 L3 对手**：读历史的对手用它决定如何对待我方，让强化学习在闭环中
   自己学到信誉成本。这是主渠道。
2. **信誉塑形项**：奖励中加 `−λ · Σ 检测器得分(我方本场)`，作为对冲手段，防止池子
   低估了同学中读历史策略的比例。

λ 是超参数，扫描后画"总分–λ"曲线，并在"读历史策略占比"不同的配比下比较，
选在高占比配比下不崩、低占比配比下损失可接受的点。不把塑形项当作主渠道，
因为它是手写先验，可能和池子里的真实惩罚重复计算或方向错误。

## 代码目录规划

```
env/         规则模拟器（对齐调试包），未知参数做成配置项
pool/        对手池 L0–L4
detectors/   检测器库
agents/      手工基线（参照尺）、强化学习智能体
training/    训练、蒸馏脚本
runtime/     纯 Python 推理与权重导出
eval/        评测：import 白名单、单次最坏耗时、5 种子
submission/  最终提交文件
tests/
```
