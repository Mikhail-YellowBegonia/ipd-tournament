# 系统架构

## 总览

```
训练端（不受限：numpy/torch）              评测端（纯标准库，对齐考试）
┌──────────────────────────┐   蒸馏(DAgger)   ┌──────────────────────────┐
│ 教师：大模型，读完整历史   │ ───────────────▶ │ 学生：n-gram 编码 + 小 GRU │
└──────────────────────────┘                  └──────────────────────────┘
        ▲  强化学习 + 辅助损失                         │ 导出权重为只读常量
        │                                             ▼
┌──────────────────────────┐                  ┌──────────────────────────┐
│ 模拟器 + 对手池 L0–L4     │ ◀──── 联盟快照 ── │ submission/gXX_*.py       │
└──────────────────────────┘                  └──────────────────────────┘
```

## 学生模型（部署形态）

1. **场内编码**：每场历史按（我方, 对手, 阶段）n-gram 计数，再乘可学习嵌入表求和。
   线性层可先计数后相乘，耗时只与词表大小有关，与历史长度无关。
2. **场间池化**：20 个场向量做带时间衰减的注意力池化；跳过隐藏场，输入有效场数。
3. **本场分析**：小 GRU 读本场动作对与位置，以历史嵌入为条件。
4. **输出**：合作概率；可用 `random` 采样，不改全局种子。

维度初定 16–32。所有推理包在 `try/except` 内，异常时有确定性兜底。

## 训练

- 主信号：强化学习，奖励 = 单场得分（可加信誉塑形项，见下）。
- 辅助损失（客观标签，来自模拟器，不构成"人类先验污染"）：
  - 预测对手下一手（用 19 场预测第 20 场）
  - 对比学习：同一策略的两场嵌入相近
- 蒸馏：学生自己下棋，教师在学生访问到的状态上给动作分布（DAgger），之后强化学习微调。
- 进化策略微调：在纯 Python 评测环境中以锦标赛总分为适应度（ADR 0005）。

## 对手池

| 层 | 内容 |
|---|---|
| L0 | AllC、AllD、Random(p)、交替、周期模式 |
| L1 | TFT、TF2T、STFT、GTFT、Grim、WSLS、Gradual、Prober、Joss、ZD 系 |
| L2 | 感知回合：最后 k 手背叛、阶段切换、倒推背叛 |
| L3 | 读历史：基于检测器库（见下）决定防范、报复或剥削 |
| L4 | 联盟：我方各代快照 + 专门针对我方的克星 |
| 外部 | 移植 Axelrod 演化策略：EvolvedANN、EvolvedLookerUp、EvolvedFSM、PSO Gambler；EvolvedAttention 仅训练端 |
| AXL | Axelrod 策略库适配器：将 axelrod 包中的策略适配为我方接口（仅训练端） |

### Axelrod 适配器

`ipd/pool/axl.py` 提供 `axelrod_agents()` 函数，将 [Axelrod](https://github.com/Axelrod-Python/Axelrod) 策略库中的策略适配为我方模拟器接口。要点：

- **状态管理**：Axelrod 的 Player 对象有状态，每场对局维护独立实例；历史不匹配时通过重放恢复状态
- **格式转换**：Axelrod 使用 `'C'/'D'`，我方使用 `'c'/'b'`
- **收益映射**：Axelrod 的 Game 固定，我方分阶段变化；选用第 0 阶段收益 `(T=4, S=-6, R=2, P=-1)` 作为映射（占比最大且策略初始化时需要）
- **过滤规则**：排除作弊策略（`inspects_source` / `manipulates_source` / `manipulates_state`）、无法构造或崩溃的策略；`long_run_time` 策略需显式包含
- **可重现性**：从全局 `random` 模块为每个策略实例设置种子

仅训练端依赖（`requirements-train.txt`），评测端不依赖 axelrod 包。

- 每个家族的参数随机采样，而非只放标准版本。
- 加噪声版本（1–15% 失误）和"出错退化为 AllC"版本。
- 用探针对手做行为指纹去重；按多种配比评估，报告平均与最差。
- 留出测试池：队友独立编写，只用于最终验收。

## 检测器库与信誉塑形

实现：`ipd/detectors/profile.py`。`profile(own_rows, opp_rows)` 单次遍历，统计以下事件的
（命中, 试验）：合作率、首手背叛、末手背叛、终局背叛段（及典型长度）、无端背叛、
报复、复读（跟随对手上一手）、剥削合作者、冷酷触发。含 `"m"` 的位置不计入试验，
平滑由调用方用 `Profile.rate(prior, strength)` 决定。`match_profile(my, opp)` 对单场打分，供塑形使用。

L3 包装器（`ipd/pool/l3.py`）：reputation_gate（对坏信誉者全程背叛）、endgame_preempt
（比对手的终局背叛再提前）、exploit_soft（剥削不报复者）、opening_mirror（对常背叛起手者背叛起手）。

检测器是对一份 20×25 历史打分的函数，例如：终局背叛、最后 N 手背叛、起手背叛、
复读（TFT 式跟随）、剥削合作者、无端背叛率。同一套检测器有两个用途：

1. **构造 L3 对手**：读历史的对手用它决定如何对待我方，让强化学习在闭环中
   自己学到信誉成本。这是主渠道。
2. **信誉塑形项**：奖励中加 `−λ · Σ 检测器得分(我方本场)`，作为对冲手段，防止池子
   低估了同学中读历史策略的比例。

λ 是超参数，扫描后画"总分–λ"曲线，并在"读历史策略占比"不同的配比下比较，
选在高占比配比下不崩、低占比配比下损失可接受的点。不把塑形项当作主渠道，
因为它是手写先验，可能和池子里的真实惩罚重复计算或方向错误。

## 代码目录规划

所有代码放在 `ipd/` 包内（避免顶层 `env/` 与虚拟环境目录重名）。✅ 为已建立。

```
ipd/sim/          ✅ 规则模拟器（对齐调试包），未知参数在 TournamentConfig 中
ipd/pool/         ✅ 对手池（已有 L0–L3）
ipd/detectors/    ✅ 检测器库
ipd/agents/       手工基线（参照尺）、强化学习智能体
ipd/training/     训练、蒸馏、进化策略微调
ipd/runtime/      纯 Python 推理与权重导出
ipd/eval/         评测：import 白名单、单次最坏耗时、5 种子
submission/       最终提交文件
tests/            ✅ 单元测试（unittest）
```

对手池中的策略与提交物使用同一九参数接口；`Agent.fn` 由模拟器按位置参数调用。
