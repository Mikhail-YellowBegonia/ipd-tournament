## 一、程序要求

### 1. 对局流程

- 每组按统一接口编写一个 Python 策略函数 `strategy`。
- 共组织 **8 轮**对局。
- 每轮所有小组两两对抗一次，不与自己对抗。
- 每场对抗包含 **25 次博弈**，双方分别返回合作或背叛。
- 可使用的信息包括：
  - 当前轮次、已完成博弈次数、双方组号；
  - 收益表、本场双方此前的决策；
  - 对手最近 20 场的决策及其对手的对应决策。

### 2. 接口与 I/O 格式

函数签名如下（参数名以调试包模板为准）：

```python
def strategy(
    rs, length, my_id, my_decisions,
    opp_id, opp_decisions, repay,
    opp_history_decisions, opp_opp_history_decisions,
):
    ...
```

返回值：

- `"c"`：合作
- `"b"`：背叛

每次调用都必须返回 `"c"` 或 `"b"`；不能只 `print`，也不能返回 `None`。

#### 参数说明

| 参数 | 含义 |
|---|---|
| `rs` | 当前轮次，`0 ~ 7` |
| `length` | 当前场中已完成的博弈次数，`0 ~ 24`；参数名不要写成内置函数 `len` |
| `my_id` | 自己的组号 |
| `opp_id` | 对手的组号 |
| `my_decisions` | 本场自己此前的决策，长度为 `length` 的元组；首回合为空元组 |
| `opp_decisions` | 本场对手此前的决策，长度为 `length` 的元组；首回合为空元组；`length > 0` 时，`opp_decisions[-1]` 是对手上一手决策 |
| `repay` | `25 × 4` 元组；`repay[length]` 是当前回合的收益参数行 |
| `opp_history_decisions` | 对手最近 20 场的决策，每场 25 步，`20 × 25` 元组 |
| `opp_opp_history_decisions` | 上述各场中，对手的对手的决策，`20 × 25` 元组 |

`repay` 每行依次为 `(T, S, R, P)`：

- `T`：单方背叛所得
- `S`：受骗损失
- `R`：双方合作
- `P`：双方背叛

历史记录说明：

- 两份历史均为 `20 × 25` 元组。
- 最新记录在最后；不足 20 场时在前面补 `"m"`。
- 已有记录也可能被随机隐藏；两份历史的对应位置会同步变为 `"m"`。

### 3. 本场收益表

本场收益按阶段变化：

| 回合索引 `length` | `T` 单方背叛所得 | `S` 受骗损失 | `R` 双方合作 | `P` 双方背叛 |
|---|---:|---:|---:|---:|
| `0 ~ 9` | 4 | -6 | 2 | -1 |
| `10 ~ 19` | 5 | -7 | 3 | -2 |
| `20 ~ 24` | 6 | -8 | 4 | -3 |

### 4. 程序赋分口径

- 每组总得分为所有对抗得分之和。
- `n` 表示参赛策略总数。
- 每组共有 `8 × (n - 1) × 25` 次决策机会。

### 5. 环境配置与本地检查

- 使用 Python 3.10 或以上版本，建议 3.11 / 3.12；只用标准库。
- 完整解压“学生调试包”，保持各 `.py` 文件位于同一文件夹。
- 修改 `strategy.py` 中的 `strategy` 函数；保留函数名和九个参数。
- 在该文件夹打开终端，保存代码后按以下顺序运行：

```bash
python validate_submission.py strategy.py
python run_local.py
python run_local.py --league
```

## 二、执行要求

### 1. 分组方式

- **3 人一组**，自由组队。
- 将各组成员信息填写在共享文档同一行内。
- 行首 ID 即为小组 ID；编号顺序不代表成绩或优先级。
- 组队截止时间：待通知。
- 未在截止日期前完成组队的同学，由课程组协调分组。
- 本届共享文档链接与二维码：待发布。

### 2. 提交内容

每组提交：

1. 一个 `.py` 策略文件；
2. 一个 `.txt` 说明文档。

具体要求：

- 保留 `strategy` 函数；可添加辅助函数、只读常量及允许的导入。
- 说明文档写明成员与分工，并简述策略原理，**300 字以内**。
- 文件命名为 `gXX_team_name.py` 和 `gXX_team_name.txt`。
- `XX` 为两位组号；`team_name` 仅含英文字母、数字和下划线。
- 保留 `strategy.py` 用于调试；复制一份并改名提交，函数名仍为 `strategy`。

### 3. 提交方式与截止时间

- 程序与说明文档提交截止时间：**12 月 15 日 15:10 前**（第十五周正课前）。
- 提交平台：教学网。
- 可多次提交，以最后一版为准。
- 每组由一名成员提交，确保代码与说明文档齐全。
- 提交后确认系统显示成功，并检查文件名与附件内容。
- 若程序存在运行问题，助教将联系小组组长修改。
- 程序修改截止时间：待通知。

### 4. 评分方式

- 基础分共 **5 分**：
  - 代码 4 分；
  - 说明文档 1 分。
- 代码评分：
  - 正常运行 3 分；
  - 编程风格良好 1 分。
- 说明文档评分：
  - 说明清晰简洁 1 分。
- 修改截止后代码仍不能正常运行，扣除运行部分的 3 分。
- 小组成员得分一致。
- 正式评测使用 5 个固定随机种子；并列情况按竞赛排名处理。
- 额外奖励分：进入前 10 名，或超过往年基准策略。

### 5. 注意事项

- 函数依据参数决策，不保存跨调用的可变状态。
- 不使用 `global`、`nonlocal` 或可变默认参数。
- 不得修改传入的历史与收益数据。
- 不读写文件、不联网。
- 不导入或调用其他组代码；辅助函数放在自己提交的文件中。
- 可以使用 `random` 生成随机决策，但不得修改全局随机数种子。
- 仅导入 README 允许的模块，不使用 `from ... import *`。
- 文件保存为 UTF-8。
- 单次决策不超过 **0.5 秒**。
- 单次决策超时、异常或返回非法值时，该回合按合作处理；同一种子内累计 3 次后，后续均按合作处理。
